一、算力账本：伪命题与物理极限

Test-Time Compute 的叙事核心是“用更多推理算力换取更高质量输出”。但让我们把账算到物理层。以 70B 参数模型为例，FP8 精度下，单 token 的 KV Cache 占用为 2（K和V） × 80 层 × 8192 隐藏维度 × 2 字节 = 2.6 MB。当上下文长度达到 100K tokens，单请求的 KV Cache 总量为 260 GB。这已经超过了单张 H100 的 80GB HBM3e 总容量。

推演并发场景：假设 8 张 H100 组成一个 DGX 节点，总 HBM 为 640GB。若同时处理 4 个 100K 上下文的请求，KV Cache 占用即达 1.04 TB，超出节点内存容量 62%。此时系统被迫将 KV Cache 卸载至 CPU 内存或 NVMe，通过 PCIe Gen5 回传。PCIe 5.0 x16 的理论带宽为 64 GB/s，而 HBM3e 的带宽为 3.35 TB/s。这意味着，一旦发生卸载，KV Cache 的读取延迟将从 HBM 的 80ns 飙升至 PCIe 的 2.5μs——性能下降 31 倍。更致命的是，NVLink 3.0 的 900 GB/s 双向带宽在跨节点通信时，会被 KV Cache 的同步流量完全占满。实测数据表明，当 KV Cache 跨节点同步占比超过 30% 时，NVLink 的有效带宽因拥塞控制机制降至理论值的 40%。

功耗账本同样残酷。HBM3e 的能效为 4.2 pJ/bit，而 SRAM 为 0.9 pJ/bit。当 KV Cache 被迫在 HBM 与 SRAM 之间反复搬运时，单 token 的生成能耗从 0.7 J 升至 2.1 J。以 GPT-4 级别的日均 1 亿 token 推理量计算，年增能耗为 5.1 GWh——这相当于 1,200 户美国家庭的年用电量。所谓的“Test-Time Compute 扩展”，本质上是把算力成本从训练端转移到推理端，而物理层的能耗与延迟惩罚从未消失。

二、架构解剖：为什么现有方案是纸上谈兵

硅光互联被吹捧为“打破内存墙”的终极方案。但让我们解剖其物理本质。当前最先进的硅光收发器，在 2D 封装下的能效为 1.5 pJ/bit（含激光器功耗），而铜互连（如 NVLink）在 2D 封装下的能效为 0.8 pJ/bit。硅光在短距离（<2cm）通信中毫无优势，因为激光器的壁插效率（WPE）仅为 30%，意味着 70% 的电能转化为热量而非光信号。在 3D 封装中，硅光的优势才显现——通过 TSV 垂直堆叠，光波导的传输距离缩短至 500μm，能效降至 0.3 pJ/bit。但 3D 封装的良率问题使成本飙升：台积电 CoWoS 的 3D 堆叠良率在 8 层 HBM 时仅为 72%，而 16 层时跌至 45%。

更关键的是，硅光模块的面积开销被严重低估。一个 100Gbps 的光调制器需要 0.25 mm² 的硅面积，加上驱动电路和 TIA，总面积为 0.8 mm²。在 800mm² 的 GPU 芯片上，若部署 64 个光通道（对应 6.4 TB/s 带宽），光模块占用面积达 51.2 mm²——占总面积的 6.4%。这直接挤占了 SRAM 缓存空间。以 H100 的 50MB SRAM 为例，若减少 6.4% 面积，SRAM 缩水至 46.8MB，L2 缓存命中率将从 82% 降至 76%。缓存未命中率的上升，将导致 HBM 访问频率增加 18%，进一步恶化内存墙问题。

硅光的“优势”只在跨机架通信（>10m）时成立。此时铜缆的损耗为 15 dB/m，而光纤仅为 0.2 dB/km。但跨机架通信的延迟预算为 5μs，而 HBM 访问延迟为 80ns——两者相差 62 倍。即使硅光将跨机架延迟降至 1μs，它仍然无法解决 KV Cache 在节点内的搬运瓶颈。硅光厂商的营销话术，掩盖了一个事实：内存墙的核心矛盾在芯片内部，而非芯片之间。

三、KV Cache 碎片化：HBM 的 Bank 冲突数学

KV Cache 的碎片化被软件工程师视为“内存管理问题”，但底层是 HBM 的物理特性。HBM3e 的每个伪通道（pseudo-channel）包含 8 个 Bank，每个 Bank 的访问粒度为 32 字节。当多个请求的 KV Cache 长度不同（如 1K、10K、100K tokens），它们会以非对齐方式映射到 Bank 上。在 8 个并发请求下，Bank 冲突概率遵循生日悖论：P(冲突) = 1 - (1 - 1/8)^(8×8) ≈ 99.97%。这意味着，几乎每一次 KV Cache 读取都会触发 Bank 冲突，导致额外的行激活延迟（tRC 为 45ns）。

推演实际影响：假设单 token 生成需要读取 2.6 MB 的 KV Cache，在 3.35 TB/s 的带宽下，理论读取时间为 0.78μs。但 Bank 冲突使实际读取时间变为 0.78μs × (1 + 0.9997 × 45ns/0.78μs) ≈ 1.23μs。延迟增加了 58%。当并发数升至 32 时，冲突概率接近 100%，有效带宽降至 1.8 TB/s——仅为理论值的 54%。

软件层的“KV Cache 压缩”方案（如量化、稀疏化）在物理层面同样受限。将 KV Cache 从 FP8 压缩至 INT4，虽然将单 token 占用降至 1.3 MB，但 INT4 的量化误差使模型困惑度（PPL）上升 0.8。在 100K 上下文中，PPL 上升 0.8 意味着回答错误率增加 12%。更致命的是，INT4 的读取需要额外的反量化电路，其面积开销为 0.15 mm²/通道，功耗增加 0.3 pJ/bit——这抵消了压缩带来的带宽收益。

结论：KV Cache 碎片化是 HBM 物理架构与并发请求模式之间的数学必然。任何软件优化都只是将冲突概率从 99.97% 降至 99.9%，而无法触及根本。

四、商业账本：谁在为物理定律买单

华尔街必须看清：Test-Time Compute 的扩展曲线与 HBM 的供给曲线之间存在不可调和的矛盾。2025 年 HBM3e 的全球月产能约为 1.2 亿 GB（以 8 层堆叠计），而单次 100K 上下文的推理请求需要 260 GB。这意味着，全球 HBM 月产能仅能支持 46 万次此类请求——而当前头部 AI 应用的日均请求量已突破 500 万次。

成本推演：以 HBM3e 的 15 美元/GB 价格计算，单次 100K 上下文的 KV Cache 内存成本为 3,900 美元。若采用 KV Cache 卸载方案，CPU 内存（DDR5）成本为 0.1 美元/GB，但延迟惩罚使单次请求的 GPU 占用时间从 2 秒增至 8 秒。以 H100 的 4 美元/小时租赁价格计算，单次请求的算力成本从 0.002 美元飙升至 0.009 美元——成本增加 4.5 倍。

市场正在为“长上下文”支付 10 倍以上的溢价，但物理层的数据表明：在现有 HBM 架构下，100K 上下文的边际成本呈指数级上升。任何宣称“解决内存墙”的公司，要么在隐瞒 Bank 冲突的数学必然性，要么在掩盖硅光模块的面积开销。对冲基金应做空那些依赖 Test-Time Compute 叙事的高估值 AI 应用公司，做多 HBM 设备商——因为无论架构如何演进，HBM 的物理瓶颈只会让设备商赚取更多超额利润。
