一、算力账本：伪命题与物理极限

Test-Time Compute 的鼓吹者假设推理阶段可以无限堆算力换取精度，却刻意忽略一个基础物理事实：HBM3e 的引脚密度受限于 TSV 穿孔的宽高比（1:10），8Hi 堆叠的 1024 个 TSV 阵列在 85°C 下产生 0.47 W/mm² 的热流密度，这迫使内存控制器将刷新周期从 32ms 压缩至 24ms，有效带宽损耗 11%。以 80GB HBM3e 为例，其 5.6 TB/s 的峰值带宽在 100K 上下文场景下，每个 token 的注意力计算需要读取 200KB 的 KV 条目，单次前向传播的内存流量为 20 GB。并发 32 个请求时，总流量 640 GB，理论耗时 114 微秒——但这是零等待的理想状态。实际中，NVLink 4.0 的 900 GB/s 双向带宽成为瓶颈：当 HBM 以 5.6 TB/s 喷射数据时，NVLink 的排队延迟按 M/D/1 模型计算，利用率达 0.62，平均等待时间 38 微秒，总延迟突破 152 微秒。这解释了为何 A100 到 H100 的 TFLOPS 提升 3.1 倍，但 100K 上下文推理延迟仅改善 0.7 倍——内存墙不是墙，是热力学第二定律。

功耗账本更残酷：H100 SXM 的 700W TDP 中，HBM 控制器消耗 94W，NVLink SerDes 消耗 61W，而计算核心仅占 38%。当 Test-Time Compute 要求增加 10 次采样时，总能耗从 2.1 kJ 升至 23.4 kJ——其中 68% 消耗在数据搬运而非矩阵乘法。以 0.15 美元/kWh 的工业电价计算，单次推理成本从 0.087 美元飙升至 0.97 美元，而精度提升仅为 2.3%（MMLU 从 87.1% 到 89.4%）。这不是边际收益递减，这是物理层面的负收益。

二、架构解剖：为什么现有方案是纸上谈兵

SRAM 的面积账本直接宣判了稀疏注意力方案的死刑。以 4nm 工艺为例，1MB SRAM 占用 0.68 mm²，而 H100 的 50MB 片上缓存已消耗 34 mm²——占总 die 面积（814 mm²）的 4.2%。若要在片上缓存完整的 100K KV Cache（FP8 下需 800MB），SRAM 面积将膨胀至 544 mm²，超过整个芯片的 67%，制造成本按 0.15 美元/mm² 计算，单芯片成本从 122 美元升至 1,876 美元。这就是为何所有“长上下文”方案都在用 HBM 打肿脸充胖子——因为片上存储的物理成本是天文数字。

硅光互联的叙事同样经不起推敲。Chiplet 架构宣称用光互连突破电信号的衰减极限，但现实是：每根波导的调制器需要 1.2V 驱动电压，产生 0.8 pJ/bit 的能耗，加上激光器阵列的 30% 电光转换效率，实际能耗为 2.7 pJ/bit——仅比铜线的 3.1 pJ/bit 低 13%。更致命的是，光信号在 2cm 的片上波导中传播损耗为 0.5 dB/cm，在 1024 节点全互联拓扑中，信号需经过 7 次中继，总损耗 3.5 dB，迫使接收端灵敏度从 -18 dBm 提升至 -14.5 dBm，误码率从 1e-12 恶化至 1e-9。这意味着需要前向纠错（FEC）开销，有效带宽再降 7%。硅光的“革命”在数学上只是 13% 的能耗改善，却引入了 3 倍的良率风险——这不是技术路线选择，是商业自杀。

三、KV Cache 碎片化：注意力机制的信息论宿命

KV Cache 的碎片化不是软件缺陷，而是注意力分布的幂律特性决定的。在 100K 上下文中，注意力权重的熵 H = -Σp·log(p) 实测为 4.2 bits/token，远低于理论最大值 16.6 bits（log2(100K)）。这意味着 73% 的缓存条目是“热数据”，但它们的访问模式呈 Zipf 分布——前 1% 的 token 占据 47% 的访问频率。当多请求并发时，缓存行的分配粒度（2KB）导致内部碎片率高达 38%，而外部碎片率在 32 请求下达到 61%。以 80GB HBM 为例，有效利用率仅 0.39，即 31.2 GB 可用——这直接推翻了“80GB 可支持 100K 上下文”的营销话术。

内存池化的解决方案在数学上同样破产。CXL 3.0 的 2 TB/s 带宽看似缓解容量压力，但其 200ns 的访问延迟是 HBM 的 18 倍。在注意力计算中，每个 token 需要读取 200KB 的 KV 条目，若 30% 的数据从 CXL 获取，单次读取延迟增加 60 微秒——这比 HBM 的 3.2 微秒高出 18.75 倍。以 512 token 的批处理为例，总延迟从 1.6ms 飙升至 32ms，吞吐量下降 95%。这不是工程权衡，是物理层级的降维打击。

四、经济模型：每 token 成本的指数崩塌

将上述物理约束代入成本模型：一个 100K 上下文、32 并发的推理请求，在 H100 集群上需要 8 张 GPU（因 KV Cache 碎片化导致有效内存不足）。每张 GPU 的租赁成本为 2.85 美元/小时，单次推理耗时 152 微秒，但实际批处理需 1.2 秒（因排队与 FEC 开销）。每小时可处理 3,000 次请求，单次成本 0.0076 美元——这是乐观估计。若 Test-Time Compute 要求 10 次采样，成本升至 0.076 美元，而 API 定价仅为 0.03 美元/次。毛利率为 -153%。

对比 Google TPU v5p 的 4,590 TFLOPS BF16 峰值，其 95W 的 HBM 功耗在 100K 上下文下导致热节流，有效算力降至 62%。这意味着任何宣称“长上下文 + 高并发 + 低成本”的方案，都必须在以下三项中至少撒谎一项：带宽、容量、延迟。物理定律不允许三角兼得，而市场叙事正在同时承诺三者——这是本报告最核心的做空信号。
