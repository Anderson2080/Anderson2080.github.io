一、算力账本：伪命题与物理极限

Test-Time Compute 的鼓吹者忽略了一个基本事实：推理延迟与内存带宽的乘积是物理常数。以 NVIDIA H100 为例，其 HBM3e 带宽为 3.35 TB/s，在 FP8 精度下，单次注意力计算需加载 2N² 个参数（N=序列长度）。当 N=100K 时，单 token 加载量达 20 GB，带宽利用率仅 60%，延迟 = 20 GB / (3.35 TB/s × 0.6) ≈ 9.9 微秒。但这只是理想状态——实际并发请求下，HBM 带宽被 8 个 GPU 共享，NVLink 带宽（900 GB/s）成为瓶颈。推演：100 个并发请求同时访问 80 GB HBM，有效带宽骤降至 1.2 TB/s，延迟飙至 27.5 微秒，远超推理 SLA 的 10 微秒红线。更致命的是，HBM3e 堆叠良率在 12 层 TSV 穿孔下仅 68%，热密度达 2.3 W/mm²，导致 30% 的带宽因热节流损失。这不是软件问题，是硅基物理的死刑判决。

二、架构解剖：为什么现有方案是纸上谈兵

多智能体并发场景下，KV Cache 碎片化是隐藏的算力黑洞。每个智能体维护独立的 KV Cache，在 100K 上下文下，单 cache 占用 1.2 GB SRAM（FP8 精度）。但 SRAM 面积受限：H100 的 80 MB SRAM 仅能容纳 66 个 cache 条目，而实际并发数达 1000 时，碎片化导致 47% 的 SRAM 空间因对齐浪费。推演：有效 cache 命中率从 95% 降至 52%，迫使 48% 的请求回退到 HBM 加载，延迟增加 8.3 微秒。硅光互联试图解决带宽瓶颈，但现状是：1.6Tbps 硅光模块的 pJ/bit 为 3.2，虽低于铜缆的 4.6，但良率仅 12%，每模块成本 $2,400，是铜缆的 7 倍。更致命的是，硅光调制器的热稳定性在 85°C 下漂移 0.7 nm，导致误码率从 1e-12 升至 1e-9，需要 30% 的纠错开销。这不是技术迭代，是物理定律的铜墙铁壁。

三、商业账本：每 token 成本的物理下限

将上述物理参数代入成本模型：H100 集群的 TCO 为 $3.2/小时（含电力、冷却、折旧）。在 Test-Time Compute 场景下，有效吞吐量仅 120 token/秒/GPU（受内存墙限制），每 token 成本 = $3.2 / (120 × 3600) = $0.0000074。但考虑 KV Cache 碎片化导致的 2.3 倍延迟惩罚，实际成本升至 $0.000017。若采用硅光互联，每 GPU 成本增加 $2,400，TCO 升至 $3.8/小时，但带宽提升 40% 使吞吐量增至 168 token/秒，每 token 成本 = $3.8 / (168 × 3600) = $0.0000063——仅节省 15%，却需 7 倍资本支出。华尔街的数学很简单：任何突破物理极限的“创新”，在 3 年折旧周期内都是负 NPV。结论：Test-Time Compute 是伪需求，HBM 内存墙和硅光良率才是唯一真实的战场。
