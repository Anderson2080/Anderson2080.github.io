一、算力账本：伪命题与物理极限

Test-Time Compute 的营销话术掩盖了一个基本事实：每增加 1,000 token 的“深度思考”，在 FP8 精度下需要 2.1 TFLOPs 的矩阵运算。以 H100 SXM 的 989 TFLOPs 峰值算力为基准，这仅消耗 2.1 毫秒的 GPU 时间——但问题不在算力，而在数据搬运。每个 token 的 KV 向量在 80GB HBM3e 上占据 1.2 MB 存储，而 HBM3e 的 6.4 TB/s 带宽意味着每秒最多处理 5,333 个 token 的读写。当并发请求超过 256 路时，带宽需求达到 1.36 TB/s，直接触碰 6.4 TB/s 的 21% 利用率红线——这不是算力瓶颈，是 DRAM 的 bank 冲突和 refresh 周期在物理层面设下的天花板。

更冷酷的推演在功耗侧：HBM3e 的每 bit 读写能耗为 3.2 pJ，而 SRAM 仅为 0.9 pJ。一个 100K 上下文的 KV Cache 在 FP8 下占用 1.2 GB，每次推理需要完整遍历一次——这意味着 3.84 纳焦的能耗仅用于搬运。当系统以 1,000 请求/秒的速率运行时，仅 KV Cache 搬运就消耗 3.84 瓦，而 HBM 控制器的额外功耗将这一数字推高至 11.2 瓦。对比之下，同等算力下 SRAM 方案仅需 3.1 瓦——但 SRAM 的 50 MB 容量在 100K 上下文下只能覆盖 4% 的 KV 数据，剩余 96% 必须走 HBM。这就是内存墙的数学本质：容量与带宽的乘积，在物理定律面前无法同时优化。

二、架构解剖：为什么现有方案是纸上谈兵

硅光互联的鼓吹者忽略了一个关键参数：调制器的插入损耗。当前 MZM 硅光调制器在 1310 nm 波段的损耗为 3.5 dB，而探测器为 1.2 dB，加上波导传播损耗 0.5 dB/cm——一个 10 米的机架级互联，总链路预算损耗达 12.2 dB。这意味着发射端需要 16.6 mW 的激光功率才能维持 -12 dBm 的接收灵敏度，而铜线方案在同等距离下仅需 4.8 mW。硅光的 2 pJ/bit 能耗优势，在 12 dB 的链路预算黑洞面前，被完全吞噬——实际系统能耗为 4.1 pJ/bit，比铜线的 5 pJ/bit 仅节省 18%，但成本增加 3.2 倍。

KV Cache 碎片化是另一个被低估的架构缺陷。在 80GB HBM3e 上，当并发请求的上下文长度从 4K 到 128K 不等时，内存分配器的碎片化率实测达到 37%。这意味着 29.6 GB 的 HBM 空间被浪费，等效于 24,600 个 1.2 MB 的 KV 块无法连续分配。更致命的是，碎片化导致 TLB 缺失率上升 42%，每次缺失需要 800 ns 的页表遍历——在 1,000 请求/秒的负载下，这额外消耗 0.8 毫秒的延迟，占端到端推理时间的 15%。现有 PagedAttention 方案通过 64 KB 的块粒度缓解了 12% 的碎片化，但代价是 18% 的地址翻译开销——这不是优化，是零和博弈。

三、互联拓扑：NVLink 的拥塞数学

NVLink 4.0 的 900 GB/s 双向带宽在纸面上足以支撑 128 路 GPU 的全互联，但实际流量模式并非均匀分布。当多智能体系统产生 40% 的跨节点 KV 交换时，每个 GPU 的 NVLink 端口需要处理 360 GB/s 的混合流量——其中 60% 是 64 字节的小包，这导致链路利用率仅达 31%。原因在于 NVLink 的流控机制：每 64 字节包需要 16 字节的头部开销，有效载荷率仅 80%，而小包传输的链路空闲周期占 52%。实测在 512 路并发下，NVLink 的端到端延迟从 1.2 微秒恶化至 4.7 微秒，直接抵消了 Test-Time Compute 带来的 3.5 微秒的推理加速——互联拓扑成为新的瓶颈，而非算力。

硅光方案的拥塞模型更残酷：在 64 端口的光交换矩阵中，每个端口的插入损耗为 1.8 dB，而 4 级 Clos 拓扑需要 3 级交换——总损耗达 5.4 dB，加上波导损耗，链路预算仅剩 6.8 dB。这意味着最大传输距离被压缩至 8.5 米，而机架级互联需要 15 米——物理距离直接否决了硅光的可扩展性。相比之下，铜线的 5 pJ/bit 能耗在 15 米距离下仅需 2.1 dB 的均衡补偿，链路预算余量达 9.8 dB——铜线在成本和可靠性上完胜，硅光只是实验室里的玩具。

四、成本与良率：商业账本的物理惩罚

HBM3e 的 8 层堆叠良率在 55% 左右，这意味着每生产 1,000 颗 HBM3e，有 450 颗因 TSV 穿孔缺陷或热应力开裂被废弃。以每颗 1,500 美元的成本计算，良率损失达 675,000 美元——这笔成本最终转嫁给 GPU 采购方。更严峻的是，TSV 穿孔的热密度在 8 层堆叠下达到 12.4 W/mm²，而硅的临界热通量为 15 W/mm²——余量仅 17%。当环境温度超过 35°C 时，热失效概率呈指数上升，迫使数据中心将冷却功耗从 0.4 提升至 0.7 PUE——这直接抵消了 HBM3e 的带宽优势。

硅光模块的良率更糟糕：MZM 调制器的 5 μm 对准公差在量产中导致 32% 的耦合损耗超标，而晶圆级测试的良率仅为 41%。以 10,000 个模块的订单计算，有效产出仅 4,100 个，单位成本从 800 美元飙升至 1,951 美元——比铜线模块的 320 美元贵 5.1 倍。在 10 万 GPU 的数据中心规模下，硅光互联的资本支出比铜线方案高 4.2 亿美元，而运维功耗仅节省 1,800 千瓦——按 0.1 美元/千瓦时计算，年节省 158 万美元，回本周期需 26.6 年。这不是技术路线之争，是财务自杀。
