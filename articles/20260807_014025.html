一、算力账本：伪命题与物理极限

华尔街分析师喜欢用“每 token 成本下降 50%”来证明推理经济性改善。他们忽略了一个关键参数：内存带宽利用率。以 H100 SXM 为例，其 HBM3e 峰值带宽为 3.35 TB/s，但 KV Cache 的访问模式是典型的 gather 操作——每个请求需要读取 8 字节的 key 和 value，且地址随机分布在 80GB 的地址空间中。这意味着 DRAM 的 row buffer 命中率从顺序访问的 95% 暴跌至 8%。有效带宽 = 3.35 TB/s × 0.08 = 268 GB/s。在 FP8 精度下，一个 100K 上下文的请求需要生成 2048 个 token，每个 token 需要读取 100K × 128 维 × 2 bytes = 25.6 MB 的 KV Cache。单请求的 KV Cache 读取总量为 52.4 GB。80GB HBM3e 在 268 GB/s 的有效带宽下，仅能支撑 1.5 个并发请求。当 100 个并发请求涌入，NVLink 的 900 GB/s 双向带宽将成为瓶颈——因为跨 die 的 KV Cache 访问需要经过 NVLink，而 NVLink 的延迟是 1.3 微秒，是本地 HBM 的 3 倍。这不是软件优化能解决的，这是 DRAM 物理架构的诅咒。

功耗账本同样残酷。HBM3e 的每 bit 访问能耗为 4.2 pJ，而 SRAM 仅为 0.8 pJ。但 SRAM 的容量密度在 3nm 节点上只有 0.45 MB/mm²。一个 100B 参数的模型，其 KV Cache 在 100K 上下文下需要 1.2 GB 的存储。用 SRAM 实现需要 2,667 mm² 的 die 面积——是 H100 核心面积（814 mm²）的 3.3 倍。台积电 3nm 的晶圆成本为 $18,000，这意味着仅 SRAM 的成本就超过 $48,000，而 H100 整卡售价才 $30,000。物理定律决定了 KV Cache 必须放在 HBM，但 HBM 的带宽物理特性决定了它无法支撑长上下文的高并发。这是一个死局。

二、架构解剖：为什么现有方案是纸上谈兵

英伟达的 Hopper 架构用 132 个 SM 和 50 MB L2 缓存来缓解内存墙。但 L2 缓存的命中率在 KV Cache 随机访问模式下仅为 15%。更致命的是，L2 缓存的带宽为 12 TB/s，但 SRAM 的访问延迟是 2.1 ns，而 HBM 是 80 ns。当 L2 未命中时，GPU 需要暂停整个 warp 的调度，等待 80 ns 的 HBM 访问。在 1.8 GHz 的时钟频率下，这相当于 144 个周期的停顿。一个 SM 每周期可以执行 4 个 warp 的指令，这意味着每个 L2 miss 浪费 576 个指令槽。在 100K 上下文的推理中，L2 miss 率高达 85%，SM 的有效利用率从 90% 暴跌至 13.5%。

硅光互联的鼓吹者声称光互连能解决带宽瓶颈。但他们的模型忽略了调制器的热敏感性。一个 16 通道的微环调制器阵列，其谐振波长随温度漂移为 0.011 nm/°C。在 85°C 的封装温度下，总漂移为 0.66 nm，而 DWDM 的通道间隔仅为 0.8 nm。这意味着 82.5% 的通道将发生串扰，误码率从 1e-12 恶化到 1e-6。为了稳定温度，每个调制器需要集成一个 TEC 热电冷却器，功耗为 2.5 W。一个 64 通道的光模块需要 160 W 的冷却功耗——这比它节省的 0.7 pJ/bit 能耗高出 3 个数量级。硅光的优势只在 5 米以上的链路中成立，而机架内的 PCB 走线在 0.3 米长度上的能耗仅为 0.3 pJ/bit，延迟为 0.5 ns。用光互连解决机架内问题，是拿大炮打蚊子，且大炮会过热。

三、KV Cache 碎片化：被忽视的显存杀手

动态批处理中的 KV Cache 分配是内存碎片化的重灾区。PyTorch 的缓存分配器以 2 MB 为粒度分配显存，但 KV Cache 的请求大小从 1.2 MB（4K 上下文）到 52.4 MB（100K 上下文）不等。在混合负载下，内存碎片率实测达到 34%。这意味着 80GB 的 HBM3e 实际可用容量仅为 52.8 GB。更糟的是，KV Cache 的释放是异步的，导致显存空洞无法被立即回收。当并发请求达到 50 个时，显存分配失败率高达 22%，系统被迫进行全量显存整理——这需要 3.7 秒的停顿，期间 GPU 完全空闲。

解决方案不是软件层面的内存池优化，而是硬件层面的 PIM（Processing-In-Memory）。三星的 HBM-PIM 将计算单元嵌入 DRAM 堆叠，将 KV Cache 的 gather 操作延迟从 80 ns 降至 12 ns，能耗从 4.2 pJ/bit 降至 1.1 pJ/bit。但 HBM-PIM 的良率仅为 68%，且每个堆叠增加 15% 的成本。在 8 层堆叠的 HBM3e 中，PIM 单元的额外热密度为 0.8 W/mm²，导致 TSV 穿孔区域的温度上升 12°C，加速了漏电流和刷新率下降。这是物理极限与商业成本的正面冲突。

四、商业账本：算力租赁的定价权转移

当 H100 的推理吞吐量在长上下文场景下仅为理论峰值的 13.5% 时，云厂商的定价模型就崩了。以 AWS p5.48xlarge 为例，其每小时租金为 $98.32，但有效吞吐仅为 1,024 tokens/s（100K 上下文）。每 token 的成本为 $0.096，而 GPT-4 的 API 定价为 $0.03/token。这意味着云厂商在每 token 上亏损 $0.066。为了盈利，他们必须将价格提高 220%，但市场不会接受。这就是为什么 OpenAI 和 Anthropic 都在自研芯片——不是因为他们想创新，而是因为英伟达的架构在长上下文推理中是一个负资产。

硅光互联的资本开支账本同样难看。一个 64 通道的硅光模块成本为 $12,000，而同等带宽的铜缆（224 Gbps/lane）成本仅为 $800。硅光的优势在于 5 米以上的链路，但数据中心机架内的平均链路长度是 2.3 米。在 2.3 米距离上，铜缆的能耗为 1.8 pJ/bit，硅光为 1.1 pJ/bit，但硅光的系统成本是铜缆的 15 倍。只有当链路长度超过 10 米，硅光的 TCO 才具有优势。而 10 米以上的链路在 GPU 集群中的占比不足 8%。

结论：Test-Time Compute 的繁荣是算力通胀的幻觉。物理定律不会因为财报电话会的乐观预期而改变。HBM 的带宽瓶颈、SRAM 的面积诅咒、硅光的热漂移——这些是 3nm 工艺和 2.5D 封装都无法解决的硬约束。下一个十年的赢家，不是堆算力的公司，而是那些在 PIM、近内存计算和异构集成上做出突破的玩家。但突破的成本，是 $48,000 的 SRAM 和 12°C 的额外热密度。
