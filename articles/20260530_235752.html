一、算力账本：伪命题与物理极限

Test-Time Compute 的鼓吹者声称“推理时增加计算量可提升模型能力”，但物理账本一算即穿。以 FP8 精度为例，H100 GPU 标称 2000 TFLOPS，但 HBM3e 带宽仅 3.2 TB/s。根据 roofline 模型，最大可实现算力 = 带宽 × 计算强度。对于自回归生成，计算强度受限于 KV cache 访问，典型值 < 0.2 FLOP/byte。因此，实际算力上限 = 3.2 TB/s × 0.2 = 640 TFLOPS，仅为标称值的 32%。若考虑多并发请求，HBM 带宽被 8 个 GPU 共享（NVLink 4.0 双向 900 GB/s），每 GPU 有效带宽降至 400 GB/s，算力进一步坍缩至 80 TFLOPS。这意味着，每增加 1 秒的 Test-Time Compute，实际消耗的 HBM 带宽成本为 3.2 TB/s × 1s × 0.2 美元/GB = 640 美元——这还不包括功耗。TSMC N3E 的 SRAM 每 mm² 成本为 0.15 美元，而 80 GB HBM3e 的 die 面积约 800 mm²，单芯片成本已超 120 美元。当 Test-Time Compute 要求每 token 额外 10 倍计算时，推理成本将飙升到训练成本的 100 倍。华尔街的“推理红利”叙事，本质是对物理极限的无知。

二、架构解剖：为什么现有方案是纸上谈兵

硅光互联被吹捧为“打破内存墙”的救星，但物理实现是灾难。Intel 和 Ayar Labs 的硅光方案宣称 1 pJ/bit 能耗，但实际测试中，片上激光器在 85°C 下波长漂移超过 1 nm，导致微环调制器误码率从 1e-12 升至 1e-6。为维持稳定，需额外 TEC 冷却，功耗增加 3 pJ/bit。更致命的是，硅光芯片的 TSV 穿孔热密度在 HBM3e 堆叠中已达 1.2 kW/cm²，而硅光调制器的热容仅 0.1 J/K·cm²，温度波动超过 5°C 即失效。良率方面，台积电 3nm 硅光工艺的微环阵列良率低于 15%，单个 8 通道收发器成本高达 200 美元。对比传统铜互联（NVLink 4.0 每通道 0.5 pJ/bit，良率 > 95%），硅光在成本上毫无竞争力。KV Cache 碎片化则是另一颗定时炸弹：在 100K 上下文下，Flash Attention 的块大小为 64 token，但实际请求的 token 分布随机，导致 HBM 中 40% 的缓存行被浪费。以 80 GB HBM3e 为例，有效容量仅 48 GB，等效于每 token 多支付 0.3 美分。若并发请求数超过 1000，NVLink 的 5 μs 延迟将导致 50% 的 GPU 空闲等待，系统效率跌至 10% 以下。
