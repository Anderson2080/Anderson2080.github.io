一、算力账本：伪命题与物理极限

FP8精度下，KV Cache字节数 = 2（K和V）× L（层数）× H（隐藏维度）× S（序列长度）× 1 Byte。Llama 3 70B：L=80，H=8192。S=100,000时，单序列KV Cache = 2 × 80 × 8192 × 100,000 = 131,072,000,000 Bytes = 131 GB。单张H100 SXM的80GB HBM3e无法容纳单条序列。若强制切分至2张卡，每Token每层需跨NVLink传输 2 × 8192 × 1 Byte = 16 KB。100K上下文下，每Token跨卡传输量 = 16 KB × 80层 = 1.28 MB。生成1个Token需传输1.28 MB，NVLink 900 GB/s双向带宽下，单卡理论极限并发Token吞吐 = 900 / 1.28 ≈ 703 Token/s。但NVLink实际有效载荷效率为78%（协议开销+CRC+重传），实际吞吐降至548 Token/s。若并发8路100K上下文请求，每路生成速率降至68 Token/s，端到端延迟从单卡的12 ms/token膨胀至147 ms/token。NVLink利用率 = (8 × 1.28 MB × 68) / 900 GB/s = 77.4%，排队延迟进入M/M/1模型的非线性区。

HBM3e的物理极限由TSV热密度决定。单颗HBM3e堆叠8层DRAM Die，TSV直径10 μm，间距40 μm，每平方毫米TSV数量 = 625。每个TSV电容约15 fF，8层堆叠总电容 = 120 fF。在1.2 V电压、6.4 Gbps/pin速率下，单TSV动态功耗 = 0.5 × 120 fF × (1.2 V)² × 6.4 GHz = 0.55 mW。单颗HBM3e 1024个数据pin，总动态功耗 = 563 mW。8颗HBM3e总功耗 = 4.5 W。但热密度才是杀手：TSV区域面积 = 1024 × (40 μm)² = 1.64 mm²，热密度 = 4.5 W / 1.64 mm² = 2.74 W/mm²。硅的热导率 = 150 W/(m·K)，结温到散热器温差 = 2.74 × 0.0001 / 150 = 1.83 K。看似可控，但DRAM刷新功耗在85°C时翻倍，125°C时数据保持时间从64 ms降至8 ms。HBM3e的85°C温度墙将有效带宽从1.2 TB/s压缩至780 GB/s，降幅35%。

二、架构解剖：为什么现有方案是纸上谈兵

硅光互联的pJ/bit账本：当前NVLink铜缆在0.5 m距离内，能效为5 pJ/bit。硅光模块（含激光器、调制器、光电探测器）的能效为2 pJ/bit，但激光器电光转换效率仅20%，实际系统能效 = 2 / 0.2 = 10 pJ/bit。在1.28 MB/token的跨卡传输量下，铜缆功耗 = 1.28 MB × 8 × 5 pJ/bit = 51.2 μJ/token。硅光方案 = 102.4 μJ/token。硅光仅在距离>2 m时因铜缆均衡器功耗激增而胜出。机架内NVLink铜缆仍是能效最优解。硅光互联的谎言在于：它解决的是距离问题，而非带宽密度问题。

KV Cache碎片化的数学本质：PagedAttention将KV Cache切分为固定大小的Block（通常16 Token）。100K上下文需6250个Block。每个Block的元数据（Block Table Entry）占32 Bytes，总元数据开销 = 6250 × 32 = 200 KB。看似微小，但GPU L2 Cache仅50 MB，200 KB元数据占用0.4% L2容量。当并发请求数达256路时，元数据总量 = 51.2 MB，直接击穿L2 Cache容量。L2 Miss率从12%飙升至67%，HBM访问延迟从350 ns膨胀至820 ns。每Token生成需访问KV Cache 80次（每层一次），L2 Miss导致额外HBM访问 = 80 × 0.67 = 53.6次。每次HBM访问64 Bytes，总数据量 = 53.6 × 64 = 3.43 KB/token。HBM3e带宽1.2 TB/s下，额外延迟 = 3.43 KB / 1.2 TB/s = 2.86 ns，但排队延迟因带宽利用率>90%而放大至微秒级。

SRAM面积局限：H100的L2 Cache 50 MB占用约250 mm²（7 nm工艺，SRAM密度0.2 MB/mm²）。若将KV Cache全部放入SRAM，131 GB需655,000 mm²，是H100 Die面积（814 mm²）的804倍。3D堆叠SRAM（如AMD 3D V-Cache）密度提升至0.5 MB/mm²，仍需262,000 mm²。物理上不可实现。KV Cache必须分层：SRAM（L2）→ HBM → NVLink → 以太网。每层延迟增加一个数量级。

三、商业账本：每Token成本的非线性爆炸

单卡H100 SXM成本$30,000，折旧3年，每小时成本 = $30,000 / (3 × 8760) = $1.14。功耗700 W，电价$0.10/kWh，每小时电费 = $0.07。总每小时成本 = $1.21。单卡100K上下文、FP8精度下，生成速率12 Token/s（受HBM带宽限制：1.2 TB/s / 131 GB × 2 = 18.3 Token/s，实际因L2 Miss降至12 Token/s）。每小时生成Token数 = 12 × 3600 = 43,200。每百万Token成本 = $1.21 / 0.0432 = $28.0。若并发8路，每路速率降至1.5 Token/s，总吞吐12 Token/s不变，但延迟从83 ms/token膨胀至667 ms/token。SLA违约率（>200 ms/token）达100%。

NVLink交换机成本：单台NVLink Switch 4端口，成本$8,000，功耗200 W。8卡H100通过NVLink Switch全互联，交换机成本$16,000（2台），功耗400 W。总系统成本 = 8 × $30,000 + $16,000 = $256,000。每小时成本 = $256,000 / (3 × 8760) + (8 × 700 + 400) × 0.001 × $0.10 = $9.74 + $0.60 = $10.34。总吞吐12 Token/s（受NVLink带宽限制），每百万Token成本 = $10.34 / 0.0432 = $239.4。是单卡方案的8.55倍。NVLink并未线性扩展吞吐，因为KV Cache传输量随并发数线性增长，而NVLink带宽恒定。

硅光互联的ROI：若将NVLink替换为硅光，能效从5 pJ/bit恶化至10 pJ/bit，但带宽密度从900 GB/s提升至3.2 TB/s（16通道×200 Gbps）。在100K上下文、8路并发下，NVLink利用率从77.4%降至21.8%，排队延迟从147 ms/token降至18 ms/token。但硅光模块成本$2,000/端口，16端口 = $32,000，总系统成本增至$288,000。每小时成本 = $288,000 / (3 × 8760) + (8 × 700 + 400 + 16 × 5) × 0.001 × $0.10 = $10.96 + $0.61 = $11.57。每百万Token成本 = $11.57 / 0.0432 = $267.8。硅光方案成本更高，但延迟满足SLA。商业决策取决于SLA罚款与成本差额的博弈。

四、结论：物理定律的清算日

Test-Time Compute范式下，KV Cache大小随序列长度线性增长，而HBM容量受TSV热密度和SRAM面积物理极限约束。FP8精度下，100K上下文单序列KV Cache 131 GB，击穿单卡80GB HBM3e。NVLink 900 GB/s带宽在8路并发下利用率77.4%，排队延迟进入非线性区。硅光互联解决距离问题，但能效恶化至10 pJ/bit，成本增加12.5%。PagedAttention的元数据在256路并发下击穿L2 Cache，L2 Miss率67%，HBM访问延迟膨胀至820 ns。每百万Token成本从单卡$28.0膨胀至8卡NVLink $239.4，硅光方案$267.8。物理定律不谈判：HBM容量、NVLink带宽、SRAM面积、TSV热密度，四个硬约束构成推理成本的非线性爆炸。市场对AI推理成本的线性外推模型，在100K上下文和FP8精度下，误差达8.55倍。
